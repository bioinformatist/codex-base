# Codex Base capability catalog

This catalog separates the portable plugin from the full Linux Nix/Home Manager
installation. “Plugin” means the contents installed by
`codex-base@bioinformatist-codex`; “Nix” includes the Home Manager module,
packages, global configuration, and linked unnamespaced skills. Explicit and
conditional triggers are intentional: installation alone does not run a skill.

| ID | Capability | Plugin | Nix / Home Manager | Trigger | Responsibility | Verification | Provenance |
|---|---|---|---|---|---|---|---|
| global-agents | Global AGENTS guidance | No | Yes | Loaded by Codex from the managed global guidance | Sets repository-independent safety, documentation routing, Git/Nix, and working defaults | Inspect the generated Home Manager `.codex/AGENTS.md` and run the Home Manager checks | Codex Base |
| docs-routing | Mintlify / Context7 routing | No | Yes | A request needs current library, SDK, API, CLI, or cloud-service documentation | Queries Mintlify Index first, then anonymous Context7, authenticated Context7 when needed, then official primary sources; accepts only relevant, version-sufficient, traceable results | Inspect `config/AGENTS.md` and the configured MCP entries in the Home Manager build | Codex Base |
| github-mcp | GitHub MCP | No | Yes | GitHub repository data or an authorized GitHub action is needed | Provides the configured GitHub MCP connection; it does not grant credentials by itself | Inspect the Home Manager Codex configuration with the GitHub token-file option set | Codex Base |
| improve | Improve advisor, runners, and reviewers | Yes | Yes | Explicit `$codex-base:improve ...` in the plugin or `$improve ...` with Nix; correctness and elegance reviews run only when behavior or structure warrants them | Audits, writes durable plans, selects execution lanes, delegates isolated implementation, applies per-step simplification checks and one Ponytail pass, and manages review/checkpoint boundaries | Run `$codex-base:improve quick` read-only; Nix also exposes `codex-improve-*` commands and `$improve` | Adapted from [shadcn-improve](https://github.com/shadcn/improve) and maintained by Codex Base |
| executor-routing | Deterministic executor routing | Yes | Yes | A reviewed plan has settled the product, architecture, compatibility, and implementation decisions and names exact paths and gates | Selects predefined Spark, standard, or deep execution from the plan; Spark is only for qualifying bounded work when access is available and is never an automatic classifier or fallback | Inspect `src/improve/config/roles.json` and the plan's routing evidence; see the official [Codex-Spark usage limits](https://learn.chatgpt.com/docs/agent-configuration/speed) | Codex Base |
| early-simplification | Early verification and simplification | Yes | Yes | A plan step changes code or tests; final and risk-triggered review follow after implementation | Verifies each changing step, then checks in-process for needless complexity; runs one final Ponytail pass and adds independent correctness or elegance review only when the corresponding risk warrants it | Inspect the plan's step checks and review record, then run its deterministic gates | Codex Base |
| grilling | Grilling | Yes | Yes | Explicit request to grill, interview, or stress-test a decision before action | Walks a dependency-aware decision tree in short interview rounds | Invoke `$codex-base:grilling` or Nix `$grilling` on a disposable decision | Adapted from [mattpocock-skills](https://github.com/mattpocock/skills) |
| ponytail-review | Ponytail Review | Yes | Yes | Explicit request to review a diff for over-engineering | Finds abstractions, dependencies, and flexibility that can be deleted or replaced with native facilities | Invoke `$codex-base:ponytail-review` or Nix `$ponytail-review` on a small diff | [ponytail](https://github.com/DietrichGebert/ponytail), bundled without patching |
| ponytail-audit | Ponytail Audit | Yes | Yes | Explicit request to audit a repository for over-engineering | Performs a whole-repository simplification audit without applying fixes | Invoke `$codex-base:ponytail-audit` or Nix `$ponytail-audit` | [ponytail](https://github.com/DietrichGebert/ponytail), bundled without patching |
| ponytail-debt | Ponytail Debt | Yes | Yes | Explicit request to collect `ponytail:` comments | Produces a read-only ledger of deliberate shortcuts and their revisit triggers | Invoke `$codex-base:ponytail-debt` or Nix `$ponytail-debt` in a repository | [ponytail](https://github.com/DietrichGebert/ponytail), bundled without patching |
| diagnosing-bugs | Diagnosing Bugs | Yes | Yes | A concrete hard bug, regression, flaky failure, or performance symptom needs root-cause diagnosis | Builds a tight reproduction loop, narrows hypotheses, and preserves redacted evidence | Invoke `$codex-base:diagnosing-bugs` or Nix `$diagnosing-bugs` with a concrete symptom | Adapted from [mattpocock-skills](https://github.com/mattpocock/skills) |
| tdd | TDD | Yes | Yes | The user explicitly asks for test-first work or a regression test before a fix | Drives behavior through red-green-refactor at settled public seams | Invoke `$codex-base:tdd` or Nix `$tdd` for a disposable behavior change | Adapted from [mattpocock-skills](https://github.com/mattpocock/skills) |
| codebase-design | Codebase Design | Yes | Yes | Module boundaries, interfaces, seams, adapters, or testability need design | Applies shared vocabulary for deeper modules, leverage, and locality | Invoke `$codex-base:codebase-design` or Nix `$codebase-design` on one interface | Adapted from [mattpocock-skills](https://github.com/mattpocock/skills) |
| domain-modeling | Domain Modeling | Yes | Yes | A glossary term, ubiquitous language, or durable architecture decision is being changed | Sharpens the domain model and records durable language decisions | Invoke `$codex-base:domain-modeling` or Nix `$domain-modeling` while changing a domain term | Adapted from [mattpocock-skills](https://github.com/mattpocock/skills) |
| merge-conflicts | Resolving Merge Conflicts | Yes | Yes | Git reports unresolved hunks during an in-progress merge or rebase | Resolves existing conflicts while preserving both sides' intent and verifies the result | Invoke `$codex-base:resolving-merge-conflicts` or Nix `$resolving-merge-conflicts` only in a disposable conflicted repository | Adapted from [mattpocock-skills](https://github.com/mattpocock/skills) |
| playwright | Playwright skill / CLI | Skill only | Skill and CLI binary | Browser inspection or Playwright-oriented automation is requested; the binary is used only when installed on PATH | Supplies a headless-first browser workflow; only the Nix surface installs the `playwright-cli` executable and Node runtime | Invoke `$codex-base:playwright-cli` to inspect guidance; in Nix, also run `command -v playwright-cli` | Adapted from [playwright-cli](https://github.com/microsoft/playwright-cli) |
| stop-slop | stop-slop | Yes | Yes | Publishable prose needs a final editing pass after facts are settled | Removes formulaic wording without changing commands, identifiers, facts, or caveats | Invoke `$codex-base:stop-slop` or Nix `$stop-slop` on disposable prose | Adapted from [stop-slop](https://github.com/hardikpandya/stop-slop) |
| handoff | Handoff | Yes | Yes | Explicit request to prepare a continuation handoff for another session | Writes one redacted, collision-resistant handoff file under a temporary directory | Invoke `$codex-base:handoff` or Nix `$handoff` with disposable context and inspect the reported temporary path | Adapted from [mattpocock-skills](https://github.com/mattpocock/skills) |
| questionnaire | To Questionnaire | Yes | Yes | Explicit request for a questionnaire that another person can answer | Writes a safe discovery questionnaire to a unique temporary Markdown file and never sends it | Invoke `$codex-base:to-questionnaire` or Nix `$to-questionnaire` with a disposable knowledge gap | Adapted from [mattpocock-skills](https://github.com/mattpocock/skills) |
| writing-agents | Writing for Agents | Yes | Yes | Substantial agent-consumed guidance such as a skill or `AGENTS.md` is being written | Makes agent guidance discoverable, scoped, and economical in context | Invoke `$codex-base:writing-for-agents` or Nix `$writing-for-agents` on disposable guidance | Adapted from [mattpocock-skills](https://github.com/mattpocock/skills) |
